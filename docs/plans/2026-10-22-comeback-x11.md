# comeback plan 2: X11 recorder

> For agentic workers: execute task by task, in order. Write the failing test first, watch it fail, then make it pass. Run every check through `brigade work verify run --target . --command "<cmd>" --capture brigade-work`. Keep real-desktop captures private: tests record only a throwaway Xvfb display, never the user's `DISPLAY`. Commits end with the co-author trailer of the tool that did the work. Do not edit `crates/comeback-core/src/keyframes.rs` (owned by the keyframes fixes).

**Goal:** `comeback record [--window | --area X,Y,W,H] [--duration S]` captures real X11 video and microphone audio, records clicks, drags and Shift-drag red ink, and feeds the existing `comeback-core` compile step. Then `comeback daemon`, `toggle` and `cancel` drive the same session from Alt+Shift+S.

**Spec:** `docs/specs/2026-10-19-comeback-v1.md` ("Capture backends", "Recording pipeline", "Compile step", CLI rows `record`, `daemon`, `toggle`, `cancel`). Plan 1 (`2026-10-19-comeback-core.md`) built the core.

## Raw media safety

A capture lives in `<captures>/.recording-<id>/` (`recording.mp4`, `audio.wav`, `session.json` marker, mode 0700, media 0600) until a bundle is complete. `compile_attached` hard-links the media into `<id>.comeback.partial/` and renames that directory into place. Only then is the work directory removed. If any step fails, an unreadable MP4 included, the work directory stays and the error prints its path. Cancel removes only its own work directory. `record` refuses an `--out` that already exists before it starts capturing.

## Found while building

- `xdotool` and other warped pointers produce no XInput2 raw motion, so motion is sampled every 10 ms while a button is held and raw events only mark presses and releases.
- `gst-launch-1.0` escapes spaces inside one argv entry, so paths and device names are passed raw, never quoted.
- `Xvfb` has no `-version` flag, which made the first version of the Xvfb tests skip silently. The tests now check `PATH`, and `COMEBACK_REQUIRE_X11_TESTS=1` turns a skip into a failure.
- Clipboard text survives the process through `xclip` forking a selection server, which `arboard` on X11 does not do.

## Corrections after review (2026-10-22)

An independent review of the first version found that it failed on real applications while every test passed, because the tests only clicked the bare root window. Each item below has a test that maps a real client window or checks the recording on disk, and was run against the first version to watch it fail.

- **Clicks and ink lost over windows.** Asking for XInput 2.0 means the server withholds raw events while any pointer grab is active, and a press on an ordinary window is a grab. XInput 2.2 delivers them regardless. The reader now requires 2.2 and says why when it is missing.
- **Shift-drag reached the application.** A synchronous passive grab on Shift+Button1 (all lock-key combinations) on the root window catches the press. Measured on Xvfb: while that grab freezes the pointer, raw events and `QueryPointer` are frozen as well, so the decision cannot wait for movement. It is made at the press: inside the recorded area `AllowEvents(AsyncPointer)` keeps the stroke, anywhere else `AllowEvents(ReplayPointer)` hands the press to the application as if the grab never existed. While our grab is active the server sends the release as a core event and no raw one, so the end of a stroke comes from that. A stationary Shift-click inside the area is therefore kept from the application too (re-injecting it with XTest was considered and left out as more risk than value).
- **Ink took clicks.** The overlay window now has an empty input region.
- **4:4:4 video.** `video/x-raw,format=I420` before `x264enc` gives High 4:2:0.
- **Float audio read as 16-bit.** PulseAudio offers 32-bit float, and the silence check read byte pairs as `i16`, which turned a quiet noise floor into loud garbage and sent it to Whisper. The WAV is now pinned to S16LE (the AAC branch converts back) and the reader follows the `fmt` chunk for PCM 16, 24 and 32 bit and float32, and errors on anything else.
- **Held hotkey.** XKB detectable autorepeat makes a held key one press, a press tracker ignores repeats of a key it believes is down, and a hotkey press that waited two seconds in the queue is dropped.
- **Encoder outliving a killed recorder.** `prctl(PR_SET_PDEATHSIG, SIGINT)` through the `libc` crate (already in the lock file) makes the encoder write EOS and finish its files. The kernel ties the signal to the spawning thread, so the encoder is spawned from the main thread. `filesink buffer-mode=unbuffered` means even a SIGKILLed encoder leaves a playable fragmented MP4. With the default buffering a killed encoder left an empty file.
- **Daemon blocked while compiling.** The finished capture is compiled on a worker thread. `status` says `compiling`, `cancel` refuses with an explanation and keeps the capture, and toggles are refused as busy instead of queued.
- **Raw media deleted when `ffprobe` fails, permissive modes, lost gestures on an X error.** The work directory is kept and named in the error. Directories comeback creates are 0700 and the media files 0600. The input thread returns what it captured with the error.

Not changed on purpose: a new raw press while another is open is still ignored. The simultaneous distinct buttons that case covers are legitimate, and no lost release was observed once XInput 2.2 is in use.

Known limit: the position of a release is read with a pointer query after the raw release event arrives, so a release followed within a few milliseconds by a warp of the pointer (scripted input, not a hand) is read at the new position. The tests pause between gestures for this reason.
